# 能力底物架构方案 (Capability Substrate)

> 自底向上、可组合、能自我生长的能力体系。
> 类比人体：干细胞 →(分化)→ 专门细胞 →(组合)→ 器官 → 系统 → 个体。
> 核心机制已在 `kernel/` 中实现并跑通（见文末「概念验证」）。

---

## 1. 核心机制：两个算子 + 一个统一类型

整套体系只靠三样东西成立：

| 元素 | 说明 | 生物对应 |
|------|------|---------|
| **统一类型 `Capability`** | 干细胞、分化细胞、组合器官**全是同一个类型**。正因如此，一个器官能被当成新干细胞去分化、当成成员去组合——结构得以**递归自相似地向上生长**。 | 细胞 |
| **分化算子 `differentiate(base, +条件)`** | 一生多（纵向特化）。给一个能力**附加固化条件**，派生出一个专门能力。条件在分化时定死，调用者无需再传。 | 干细胞受信号分化 |
| **组合算子 `compose(members, wiring)`** | 多合一（横向聚合）。用 wiring（数据流）把多个能力拼成一个功能单元；返回值**仍是 Capability**，可继续被组合/分化。 | 细胞聚成组织/器官 |

> 这是你纠正我的关键点：体系的主角是**分化（派生）**，不只是组合（拼装）。
> 你只维护少数"干细胞"+一套"加条件"的规则，绝大多数能力是**派生**出来的；
> 干细胞一升级，整条谱系自动继承——这才是"从底层往上长"真正成立的机制。

## 2. 五层结构（映射到具体资源）

```
L5 个体层   全自动管线（数据 → 投稿级初稿）          ← 顶层编排器 / Wei / start-army
L4 系统层   数据系统 · 分析系统 · 写作系统            ← 器官再组合
L3 器官层   现有 29 个 skills（stat-analysis 等）     ← 用组合算子重新表达
L2 分化层   抽取基线 · 组间比较 · 检索文献 …（海量、廉价、可按需现场分化）
L1 干细胞   语言 · 计算 · 存取 · 检索 · 通信（少数、未特化）
L0 资源层   LLM 推理 · 统计计算 · 存储 · 集成 IO       ← 下面这张表
```

### L0 资源层 —— 不限于本地，凡"花钱或花操作能拿到"的都算

| 资源类别 | 具体资源（当前可获取） | 绑定到哪个干细胞 |
|---------|----------------------|-----------------|
| **LLM 推理** | Claude（Fable/Opus/Sonnet/Haiku）、Gemini、GPT/Codex；多模型网关按任务分层路由 | 语言细胞 |
| **确定性计算** | Python（pandas/scipy/statsmodels/lifelines）、R（survival/meta） | 计算细胞 |
| **存储 / 状态** | Cloudflare D1（谱系表/客户表）、KV（条件缓存）、R2（数据集/产物）、Google Drive、本地 FS | 存取细胞 |
| **检索 / 知识** | Web 搜索、文献库（PubMed 等）、Notion 知识库 | 检索细胞 |
| **集成 / IO** | Gmail（获客/沟通）、Google Calendar（排期）、GitHub（代码/版本）、Notion（客户协作） | 通信细胞 |
| **执行环境** | Cloudflare Workers（无服务器算子执行）、本地进程 | 全部 |

> 资源不是根本限制：缺一个就接一个（装库 / 开 API / 连 MCP）。
> 架构对资源**透明**——干细胞背后是哪种资源，上层器官完全不感知。

## 3. 横切面机制（让体系活起来）

- **谱系注册表（Registry → 落到 D1 表）**：记录每个能力体的 `id / kind / parents / conditions`，
  可随时还原生长树、做溯源、做回滚。直接对齐 `evolution.md` 红线「进化必须可追溯、可回滚」。
- **统一契约（JSON schema）**：每个能力体的 input/output 用 schema 描述。
  这是递归组合的命门——上层只认契约，不认内部实现。
- **模型分层路由**（对应 evolution.md 原则4）：语言细胞按任务四维特征（复杂度/精度/时效/成本）
  路由不同档位模型——审查用强档（Opus），分析/写作用均衡档（Sonnet），辅助用轻档（Haiku）。
- **进化 = 对能力图做结构手术**：把 `evolution.md` 的 L1–L4 进化落到谱系上——
  AAR 里反复出现的成功 → **固化为一个新分化细胞**；反复出现的失误 → **给器官插一个检查细胞**。
  进化从"改 prompt"升级成"在能力图上长新结构 / 重组器官"，自然可追溯、可回滚。

## 4. 关键设计决策（已定的默认值）

1. **契约用代码/schema 固定，执行后端可插拔**。底层确定性（统计纯算、可复现），
   语言层背靠 LLM。当前无 API key，用离线 `StubLLM` 跑通机制，`AnthropicLLM` 接口一致即插即用。
2. **wiring 分层混用**：底层器官用**确定性 DAG**（可控、可复现，契合医学零容错）；
   顶层个体层可由一个 **LLM「编排细胞」动态规划**调用哪些器官（灵活应对没预设的任务）。
3. **复用而非另起炉灶**：现有 29 skills / 10 agents / capability-registry / evolution 全部并入——
   skills 折叠为 L3 器官，agents 是"器官的人格化视角"，evolution 成为谱系的生长引擎。
