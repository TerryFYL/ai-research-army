# 04 · 经验教训（AAR 式）

> 格式对齐 `agents/evolution.md` L1：做对了什么 / 判断失误了什么 / 下次改什么。
> 标 ⭐ 的是高频、强可迁移、建议固化为行为模式的。

## ❌→✅ 判断失误（被纠偏后修正）

1. ⭐ **把"自底向上"只讲成"组合(搭积木)"，漏了"分化(一生多)"。**
   - 失误：默认 bottom-up = 多个原子拼装；用户用干细胞分化点醒。
   - 下次改：遇"从底层长出能力"的体系，**先问有没有"一个底层派生多个上层"的分化维度**，再谈组合。

2. ⭐ **用"单个任务的执行剧本"回答"搭体系/从0到1"的问题（altitude 错位）。**
   - 失误：写了一条"曙光心衰→初稿"的任务流，用户说"这不是我要的，我要体系"。
   - 下次改：听到"体系 / 从0到1 / 各种各样的任务"，交付物是**会自己长出解法的机器**，不是某个产物的完成。

3. **第一版完成定义只列了我能想到的三五条（格式/图片/引用）。**
   - 失误：靠枚举，必漏。
   - 下次改：把标准当成 `f(目标,类型)` 的**生成程序**，从权威源头编，而不是手列清单。

## ✅ 做对了（建议固化）

4. ⭐ **每个抽象都配一个能跑的最小实证。**
   - demo（分化/组合）、emergence（相变曲线）、loop（自修订收敛）、auditor（逮出 5 条红含数字不一致）。
   - 价值：用"跑给你看"代替"讲给你听"，既验证想法、又让对方真正"看到效果"。固化。

5. ⭐ **先长神经、不急着加器官。**
   - 发现已有 29 个 skill（器官）几乎覆盖，缺的是把它们连成活体的编排（神经）。
   - 价值：涌现靠连接不靠堆器官。诊断一个系统时先看"连接/编排"缺不缺，再谈加功能。

6. ⭐ **"完成定义"要先于产出，且 scope 先判。**
   - 套标准时第一条 `scope_fit` 立刻亮红（单中心回顾队列不契合 Nature 旗舰）→ 换 NCVR 解。
   - 价值：标准在动笔前就替你做投稿现实判断。先定 done、先判 scope，省掉白做。

7. ⭐ **宁可 escalate，绝不伪造。**
   - 闭环走到"参考缺 DOI"时没有编一个，而是按红线上报"需文献库核对"。
   - 价值：自动化循环最大的失败模式是自欺；一条"不可伪造"硬约束是可信度地基。固化为循环硬规则。

8. **没有 API Key 就用可插拔 Mock 后端先把结构闭环。**
   - StubLLM/AnthropicLLM 接口对齐，离线把机制全跑通，真实后端最后接。
   - 价值：缺资源不等于停工；先闭结构、后接真实，风险最低。

9. **把每次纠偏当信号，先复述确认再动手。**
   - 多次"先理解我的意思"挡住了跑偏。
   - 价值：理解成本远低于返工成本；模糊需求先对齐。

## 一句话沉淀
> **想法要降到能跑的代码；体系要长神经不堆器官；完成要可客观验证；红线是宁可上报绝不伪造。**
