# 本地案例库 (Case Library)

> 把"从实战里长出来的认知"固化成**可检索、可复用**的案例。
> 这是 `agents/evolution.md`「经验沉淀」哲学的落地容器——沉淀不写下来 = 没发生过。

## 为什么有这个库

我们在探索/交付过程中产生大量**一次性就流失**的东西:想清楚的思想、走通的过程、造出的机制、
踩过的坑、以及对话里逼出方案的那条推理线。本库把它们按统一结构沉淀下来,供后续项目直接取用。

## 案例类型

| 前缀 | 类型 | 存放 | 例 |
|------|------|------|----|
| `C0xx` | **客户交付案例** | `public_release/`（公开镜像） | C052（已发表稿件 + 复现脚本 + STROBE 清单） |
| `RD-0xx` | **研发 / 方法论案例** | 本库 `case-library/` | RD-001（能力体系自底向上的架构探索） |

## 每个案例的"五件套"沉淀结构

用户指定的沉淀维度,每案一套(见 `_TEMPLATE/`):

| 文件 | 沉淀什么 | 回答 |
|------|---------|------|
| `01-思想.md` | 思想精华 | 想明白了什么可迁移的道理 |
| `02-过程.md` | 过程复盘 | 这套认知是按什么顺序、什么方法长出来的 |
| `03-机制.md` | 机制清单 | 造出了哪些可复用的机制/代码,入口在哪 |
| `04-经验.md` | 经验教训(AAR 式) | 做对了什么、判断失误了什么、下次改什么 |
| `05-采访记录.md` | 采访 / 对话记录 | 方案是被哪些提问与纠偏一步步逼出来的 |

外加一张**案例卡** `README.md`（摘要 / 标签 / 产出 / 链接 / 开放线索）。

## 怎么沉淀一个新案例

1. 复制 `_TEMPLATE/` 为 `<前缀>-<编号>-<短名>/`。
2. 填案例卡 + 五件套。**经验**与**采访记录**优先写——它们最易流失、最难重建。
3. 在上面索引表登记一行。
4. 客户案例的可公开产物镜像到 `public_release/`。
